## 1. 【要対処】同梱トークンが公開リポジトリで読める

**現状のリスク（本設計とは独立した既存の問題）**

- `wp-security-guard` リポジトリは **PUBLIC**
- `includes/class-inspect-token.php:55` の `DEFAULT_TOKEN` が平文でコミットされている
- GitHub API 経由で誰でも取得できることを確認済み

これにより、**第三者が 68 クライアントサイトの下記情報を読み取れる状態**にある。

- インストール済みプラグインの一覧とバージョン（`/inspect/plugins`）
- テーマ名とバージョン（`/inspect/theme`）
- 機能フラグ・ヘルス情報（`/inspect/features`, `/inspect/health`）

プラグイン一覧とバージョンは、既知の脆弱性を持つ版を探す下調べにそのまま使える情報。
membership / stripe の機微情報は `explicit` トークン限定なので漏れていない（v2.7.0 のモード概要は `default` でも取得可）。

**対処案（どれを採るか要判断）**

| 案 | 内容 | 影響 |
|---|---|---|
| A | リポジトリを **Private 化** | 最小の変更で塞がる。plugin-update-checker は `WPSG_UPDATE_TOKEN` 対応済みだが、**各サイトに定数追加が必要**になる（69件の手作業）ため要検証 |
| B | 既定トークンを**ローテーション**し、ソースから外して**ビルド時に注入** | 公開リポジトリのまま塞げる。リリース手順の変更が必要 |
| C | 既定トークンでの読み取りを**許可IP制限**と併用 | `OPTION_ALLOWED_IPS` は実装済みだが全サイトへの設定が必要 |

**本設計の書き込み機能は、この既定トークンを一切使わない**（後述）。よって上記の対処と独立して進められるが、
読み取り側の露出は別途ご判断いただきたい。

## 2. 認証設計 — なぜトークンではなく公開鍵署名にするか

書き込みを既定トークンに許すことは論外（§1）。かといって `explicit` トークン必須にすると、
69サイトへ個別にトークンを設定する手作業が発生し、「一気にやる」という目的が崩れる。

**採用案：Ed25519 の公開鍵署名**

```
WPSM（集中管理側）   秘密鍵を保持。リクエストに署名する
WPSG（各サイト）     公開鍵のみ同梱。署名を検証する
```

- プラグインのソースが公開されていても、得られるのは**公開鍵だけ**＝書き込みは不可
- **各サイトでの設定作業がゼロ**。自動更新で配布するだけで有効になる
- PHP 7.2+ に標準同梱の sodium (`sodium_crypto_sign_verify_detached`) を使用。追加依存なし

**署名対象（canonical string）**

```
{HTTPメソッド}\n{ルート}\n{site_url}\n{timestamp}\n{nonce}\n{リクエストボディのSHA-256}
```

| 要素 | 目的 |
|---|---|
| `site_url` を含める | 他サイト宛の署名を使い回せない |
| `timestamp` | 有効期限 60 秒。時計ズレ許容 ±300 秒 |
| `nonce` | transient に 600 秒記録し、再送を拒否（リプレイ防止） |
| ボディのハッシュ | 改ざん検知 |

**sodium が無い環境**は書き込みを拒否する（安全側に倒す）。可用性は `/seo/scan` が報告するので、
展開前に対象サイトの充足を確認できる。

## 3. エンドポイント

### 3.1 `GET /wpsg/v1/seo/scan` — 点検（読み取り）

既定トークンで可。**現在の WPSM 側チェックは外形（HTML取得）だが、これは DB を直接読むので正確**。

返す内容:

```jsonc
{
  "sodium": true,                       // 書き込み可否の前提
  "seo_plugin": "yoast",                // yoast | aioseo | rankmath | none
  "pages": [                            // 対象4種の候補ページ
    { "id": 12, "type": "page", "slug": "company", "title": "会社概要",
      "kind": "company",                // company | tokushoho | privacy | terms
      "noindex": false,                 // 現在の設定
      "has_company_name": true,         // 本文に会社名
      "has_rep_name": true,             // 本文に代表者名
      "url": "https://.../company/" }
  ],
  "meta": {                             // 作業5の対象
    "front_title": "…", "front_desc": "…",
    "title_template": "…", "desc_template": "…",
    "hits": { "title": true, "desc": true }
  },
  "footer": {                           // 作業4の対象
    "theme": "onlinesalon_theme", "is_child": false,
    "copyright_source": "theme_option|template", "text": "Copyright© …"
  },
  "occurrences": [                      // 作業3の抽出（除去は手作業）
    { "post_id": 34, "field": "post_content", "excerpt": "…株式会社◯◯が運営する…" }
  ]
}
```

ページ種別の判定はスラッグ・タイトルの候補リストで行い、**判定できなかったものは `kind: null` で返す**
（推測で確定させない。WPSM 側で目視・手動割当できるようにする）。

### 3.2 `POST /wpsg/v1/seo/apply` — 適用（書き込み・署名必須）

```jsonc
{
  "dry_run": true,                      // ★既定 true。false は明示指定時のみ
  "ops": [
    { "op": "page_noindex", "post_id": 12, "value": true },
    { "op": "meta_desc", "scope": "front", "value": "…" },
    { "op": "meta_title", "scope": "front", "value": "…" },
    { "op": "footer_filter", "value": "on" }
  ]
}
```

`dry_run: true` は**変更前後の差分だけを返す**。`false` で初めて書き込む。

### 3.3 `POST /wpsg/v1/seo/rollback` — 復元（署名必須）

`_wpsg_seo_backup` に保存した変更前の値へ戻す。適用単位（バッチID）を指定して一括復元。

## 4. 安全装置

| 装置 | 内容 |
|---|---|
| dry_run 既定 ON | `false` の明示指定がなければ絶対に書き込まない |
| バックアップ必須 | 変更前の値の保存に失敗したら、その操作は実行しない |
| 操作のホワイトリスト | `page_noindex` / `meta_desc` / `meta_title` / `footer_filter` の4種のみ。任意のメタ更新は受け付けない |
| 対象の限定 | `page` / `post` のみ。Yoast の noindex メタ以外の設定には触れない |
| 件数上限 | 1リクエストあたり 50 操作まで |
| 監査ログ | 誰が・いつ・何を変えたかを option に追記（直近100件） |
| 無効化定数 | `define('WPSG_DISABLE_SEO_WRITE', true)` で当該サイトの書き込みを完全遮断 |

**フッター（作業4）について — 検出のみに決定**

本文テキスト（作業3）と同じ扱いとし、**検出だけを行い自動修正はしない**。
指示書が「全ページに影響するためテンプレートファイルでの修正が効率的」としているので、
修正計画がそのまま立てられるよう次の6か所を走査する。

| 走査対象 | 返すもの |
|---|---|
| テンプレートファイル | **ファイル名＋行番号＋該当行**（子テーマ・親テーマ両方） |
| オプション | キーと値（`copyright`/`footer`/`company` を含むもの） |
| theme_mods | キーと値 |
| ウィジェット | ウィジェット位置と値 |
| **ナビメニュー項目** | メニュー名・テーマ位置・項目ラベル |
| **サイト名(blogname)** | 値 |

ナビメニューとサイト名を含めたのは実サイト調査の結果による。**テンプレートに著作権表記が
無いのに `<footer>` 内へ会社名が出ているケース**があり（onlinesalon 系＝対象16件中11件）、
フッターメニューの項目名やサイト名が発生源になりうる。

該当行は **会社名・代表者名を含む行を `high`、著作権表記だけの行を `low`** に分類して
high を先頭へ並べる。開発会社名の定型表記（`Copyright (C) 2022 Aquze LCC` が66行など）に
本命が埋もれるのを防ぐため。

走査は 400ファイル / 1ファイル300KB を上限とし、`node_modules`・`vendor`・資産ディレクトリは除外、
階層は2階層まで。実測で 12〜44ms。

## 5. 展開手順（指示書の「チェック→確認→修正」に従う）

1. WPSG v2.9.0 を実装 → GitHub リリース
2. 自動更新で全サイトへ配布（実績値で約1週間、cron的には24〜48時間で大半）
3. `/seo/scan` を全件実行 → WPSM の SEO対策ページに一覧表示 → **ユーザー確認**
4. `dry_run: true` で全件の差分を提示 → **ユーザー確認**
5. **1サイトだけ**本適用 → 表示・検索結果・Yoast出力を検証 → **ユーザー確認**
6. 全件適用
7. `/seo/scan` を再実行して漏れがないことを確認

作業3（本文テキスト）は scan の `occurrences` を WPSM に表示するところまで。
**除去は1件ずつ提案→承認→適用**とし、一括置換は行わない。
